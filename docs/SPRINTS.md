# Plan de sprints
Les sprints sont des lots de fonctionnalité et **non des promesses de durée**. Pour chacun : branche `feat/Sx-...`, PR, tests, notes de validation et mise à jour du backlog.

| Sprint | Contenu | Démonstration / gate |
|---|---|---|
| S0 | PRD, architecture, ADR, CI docs | structure et documentation cohérentes |
| S1 | Import YAML/SQLite Cu, Al, SiO₂ | n/k avec citations et domaine valide |
| S2 | Fresnel + TMM + absorption | cas air/SiO₂/Cu testé |
| S3 | Laser, soleil, lampe | simulations sourcées et unités contrôlées |
| S4 | Touloukian/EKHI + API | comparaison documentée et API vérifiée |
| S5 | Catalogue, éditeur, R3F | premier parcours intégré laser → résultats |
| S6 | Comparateur, exports, sauvegarde, QA | V1 complète et E2E |
| S7 | Docs, compte rendu, release | installation reproductible, démo |

**Definition of Done sprint :** artefacts versionnés, tests pertinents verts, hypothèses scientifiques documentées, PR revue. L'existence de fichiers ne suffit pas à clôturer un sprint.
